## Data

Download from Kaggle into `data/` (git-ignored, never committed):

```text
data/
  train.csv               10,000 labeled (5,000 human / 5,000 AI)
  unlabeled.csv            3,000 unlabeled (optional semi-supervised use)
  test.csv                 3,000 hidden-label Kaggle evaluation set
  train_starter_2000.csv   2,000-row subset of train.csv — do NOT concatenate with train.csv
```

Rules we follow: no Kaggle test labels or attempts to recover them (RAID or elsewhere), no external LLM APIs to label/predict test passages, and validation examples never enter training for controlled experiments.

Text is not cleaned or lowercased by the shared loader; casing, punctuation and formatting may be signal. Each model decides its own preprocessing, fitted on the training partition only.

Column names are auto-detected (`src/data.py`, `TEXT_CANDIDATES` / `LABEL_CANDIDATES` / `ID_CANDIDATES`). Run `python -m src.data inspect` after downloading to confirm them.

## Shared validation protocol

A fixed stratified split of `train.csv`: **8,000 train / 2,000 validation, seed 42**, via `sklearn.model_selection.train_test_split`.
Rows are put in canonical order first (sorted by ID column, or file order if there is none). The split file stores
both the positional indices and the example IDs, plus the SHA-256 of `train.csv` so a mismatched file is caught.

```bash
python -m src.data inspect   # validate files, class balance, duplicates -> results/data_report.json
python -m src.data split     # ONE teammate runs this once; commit splits/split_seed42.json
python -m src.data verify    # everyone else: confirm their local train.csv matches the split
```

`split` refuses to overwrite an existing split file (`--force` exists, but only use it if the whole team agrees and reruns everything).

In code, every model gets its data the same way:

```python
from src.data import load_split
s = load_split()   # s.train_texts, s.train_labels, s.train_ids, s.val_texts, s.val_labels, s.val_ids
```

**Duplicates / leakage.** `inspect` reports exact, whitespace/case-normalized, and near-duplicate
(TF-IDF cosine ≥ 0.9) passages, and — once the split exists — how many near-duplicate pairs straddle
train/val. If that number is non-zero, the proposed deterministic fix is: group duplicates with
union-find over the reported pairs, then assign each whole group to the side of its lowest-ID member
in the seed-42 split, and record the change in the split file.

Findings on the real data (`python -m src.data inspect`): headers `id,text,label` (test/unlabeled: `id,text`);
row counts and 5,000/5,000 balance as specified; no missing values, no exact or normalized duplicates; starter
file is a strict subset of train; no train text appears in unlabeled or test. Two near-duplicate pairs in train
(IDs 1292/5070 and 1486/4072, cosine ≈ 0.95, all four labeled AI), and both pairs straddle train/val. With 2 of
2,000 validation rows affected the AUROC impact is negligible, so the plain seed-42 split is kept unchanged.

## Model interface

See `src/classifiers/base.py`. Any object with:

```python
model.fit(train_texts, train_labels)          # training partition only
probs = model.predict_proba(texts)            # 1-D np.ndarray of P(AI) in [0,1], same order as input
model.get_config()                            # JSON-serializable hyperparameters + seed
```

can be evaluated with one call:

```python
from src.data import load_split
from src.evaluate import evaluate_classifier
result = evaluate_classifier(model, load_split(), model_name="logistic_regression", seed=42)
```

Neural models may use their own training loop instead and finish with:

```python
from src.evaluate import Timer, record_experiment
with Timer() as t:
    ...  # train
result = record_experiment("text_cnn", split, train_probs, val_probs, t.seconds, seed=42, hyperparameters=cfg)
```

Use `src.utils.set_seed(seed)` at the top of every run. If you need early stopping or tuning,
hold it out from the 8,000 training examples, not from the 2,000 validation examples.

## DistilBERT (Marcos)

Code: `src/classifiers/distilbert.py` (model), `experiments/distilbert_train.py` (one run),
`experiments/distilbert_grid.py` (comparison), `experiments/distilbert_plots.py` (figures).

**Model.** `distilbert-base-uncased` + 2-way sequence-classification head; truncation to 512 tokens with
dynamic padding per batch; AdamW (weight decay 0.01, none on bias/LayerNorm), linear LR decay, no warmup,
grad-norm clip 1.0; P(AI) = softmax(logits)[:, 1]. Device auto-selected (CUDA → MPS → CPU).

**Seeds.** Split seed 42; training seed 42 (`set_seed` + seeded DataLoader shuffling). GPU/MPS kernels are
not bit-for-bit deterministic, so reruns can differ in the last decimals.

**Commands** (run from `submissions/team-10/` with the venv active):

```bash
# smoke test (~20 s): 64 balanced train + 64 val examples, short sequences
python -m experiments.distilbert_train --limit 64 --max-length 128 --epochs 2

# baseline: lr 2e-5, batch 16, 3 epochs, max length 512
python -m experiments.distilbert_train

# staged comparison (resumable; skips runs whose metrics JSON exists)
python -m experiments.distilbert_grid

# figures from recorded results
python -m experiments.distilbert_plots

# DistilBERT unit tests (tiny random model, CPU)
pytest tests/test_distilbert.py
```

**Hyperparameter grid.** Instead of all 9 combinations: stage 1 compares learning rates 2e-5 / 3e-5 / 5e-5 at
3 epochs; stage 2 tries 2 and 4 epochs at the stage-1 best learning rate (5 runs). Batch size 16 and max
length 512 are fixed. Selection is by validation AUROC only; `test.csv` is never used.

**Checkpoint selection.** Each run evaluates the validation set after every epoch and keeps the epoch with the
best validation AUROC. The validation set is never used for gradient updates, but because it selects both
the epoch and the hyperparameters, the reported validation AUROC of the chosen configuration is slightly
optimistic.

**Outputs.**

| What | Where | In git? |
|---|---|---|
| Per-run metrics + per-epoch losses/AUROC | `results/metrics/distilbert_*.json` | yes |
| Run summary (config, time, train/val AUROC) | `results/distilbert_experiments.csv` | yes |
| Validation predictions (`id,label,prob_ai`) | `results/predictions/distilbert_*_val.csv` | no (regenerate) |
| Figures | `results/figures/distilbert_*.png` | yes |
| Best checkpoint per run (~260 MB each) | `checkpoints/distilbert/<run_name>/` | no |

`train_time_seconds` is the wall time of `fit`, including the per-epoch validation passes used for checkpoint selection.

**Inference without retraining.**

```python
from src.classifiers.distilbert import predict_proba_from_checkpoint
probs = predict_proba_from_checkpoint(list_of_passages, "checkpoints/distilbert/<run_name>")
# 1-D numpy array of P(AI) in [0, 1], same order as the input
```

## Logistic regression (Joshua)

Code: `logreg/features.py` (text cleaning + feature blocks), `logreg/model.py` (single and stacked
logistic regression), `logreg/ablation.py` (which blocks help), `logreg/stack.py` (stacked model + submission).
Seed 42, same 8k/2k split as every other model.

Feature blocks: word 1-2-gram TF-IDF, char 3-5-gram TF-IDF, 20 style features, 6 GPT-2 log-probability features.
The stacked model trains one logistic regression per block and combines their out-of-fold scores with a
meta logistic regression.

```bash
# from submissions/team-10/
python -m logreg.ablation   # one logreg per block combo, C by 5-fold CV -> results/logreg/ablation.json + metrics/
python -m logreg.stack      # stacked model, words-C sweep, test-like check, refit on all 10k
                            # -> results/logreg/stack_sweep.json + submissions/logreg_stacked_wordsC<C>.csv
pytest tests/logreg -q      # logreg unit tests
```

Notes:
- The first run scores every passage with pretrained GPT-2 and caches it to `results/logreg/lm_cache_gpt2.csv`
  (gitignored), so later runs skip it. Without torch/transformers the GPT-2 block is skipped.
- The TF-IDF vocabulary and the test-like check use unlabeled text from `unlabeled.csv` and `test.csv`
  (never test labels).
