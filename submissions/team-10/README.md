## Data

Download from Kaggle into `data/` (git-ignored, never committed):

```text
data/
  train.csv               10,000 labeled (5,000 human / 5,000 AI)
  unlabeled.csv            3,000 unlabeled (optional semi-supervised use)
  test.csv                 3,000 hidden-label Kaggle evaluation set
  train_starter_2000.csv   2,000-row subset of train.csv — do NOT concatenate with train.csv
```

Rules we follow: no Kaggle test labels or attempts to recover them (RAID or elsewhere), no external LLM APIs to label/predict test passages, and validation examples never enter training for controlled experiments.

Text is not cleaned or lowercased by the shared loader; casing, punctuation and formatting may be signal. Each model decides its own preprocessing, fitted on the training partition only.

Column names are auto-detected (`src/data.py`, `TEXT_CANDIDATES` / `LABEL_CANDIDATES` / `ID_CANDIDATES`). Run `python -m src.data inspect` after downloading to confirm them.

## Shared validation protocol

A fixed stratified split of `train.csv`: **8,000 train / 2,000 validation, seed 42**, via `sklearn.model_selection.train_test_split`.
Rows are put in canonical order first (sorted by ID column, or file order if there is none). The split file stores
both the positional indices and the example IDs, plus the SHA-256 of `train.csv` so a mismatched file is caught.

```bash
python -m src.data inspect   # validate files, class balance, duplicates -> results/data_report.json
python -m src.data split     # ONE teammate runs this once; commit splits/split_seed42.json
python -m src.data verify    # everyone else: confirm their local train.csv matches the split
```

`split` refuses to overwrite an existing split file (`--force` exists, but only use it if the whole team agrees and reruns everything).

In code, every model gets its data the same way:

```python
from src.data import load_split
s = load_split()   # s.train_texts, s.train_labels, s.train_ids, s.val_texts, s.val_labels, s.val_ids
```

**Duplicates / leakage.** `inspect` reports exact, whitespace/case-normalized, and near-duplicate
(TF-IDF cosine ≥ 0.9) passages, and — once the split exists — how many near-duplicate pairs straddle
train/val. If that number is non-zero, the proposed deterministic fix is: group duplicates with
union-find over the reported pairs, then assign each whole group to the side of its lowest-ID member
in the seed-42 split, and record the change in the split file.

Findings on the real data (`python -m src.data inspect`): headers `id,text,label` (test/unlabeled: `id,text`);
row counts and 5,000/5,000 balance as specified; no missing values, no exact or normalized duplicates; starter
file is a strict subset of train; no train text appears in unlabeled or test. Two near-duplicate pairs in train
(IDs 1292/5070 and 1486/4072, cosine ≈ 0.95, all four labeled AI), and both pairs straddle train/val. With 2 of
2,000 validation rows affected the AUROC impact is negligible, so the plain seed-42 split is kept unchanged.

## Model interface

See `src/classifiers/base.py`. Any object with:

```python
model.fit(train_texts, train_labels)          # training partition only
probs = model.predict_proba(texts)            # 1-D np.ndarray of P(AI) in [0,1], same order as input
model.get_config()                            # JSON-serializable hyperparameters + seed
```

can be evaluated with one call:

```python
from src.data import load_split
from src.evaluate import evaluate_classifier
result = evaluate_classifier(model, load_split(), model_name="logistic_regression", seed=42)
```

Neural models may use their own training loop instead and finish with:

```python
from src.evaluate import Timer, record_experiment
with Timer() as t:
    ...  # train
result = record_experiment("text_cnn", split, train_probs, val_probs, t.seconds, seed=42, hyperparameters=cfg)
```

Use `src.utils.set_seed(seed)` at the top of every run. If you need early stopping or tuning,
hold it out from the 8,000 training examples, not from the 2,000 validation examples.

## Recording results

Each call to `evaluate_classifier` / `record_experiment` writes:

- `results/metrics/<model>_<UTC timestamp>.json` — committed. Fields: `model`, `seed`, `train_auc`, `val_auc`,
  `train_time_seconds`, `hyperparameters`, full `train_metrics`/`val_metrics` (accuracy, precision, recall, F1,
  confusion matrix), `git_commit`, `notes`.
- `results/predictions/<run>_val.csv` — columns `id,label,prob_ai`, one row per validation example. Git-ignored
  by the course `*.csv` rule; regenerate locally.

```python
from src.evaluate import load_all_results
load_all_results()   # DataFrame comparing every recorded run
```

1. Set up the environment and download the data as above.

3. Run each model's experiment script (to be added under `experiments/` by each owner) with the seed recorded in its metrics JSON.

## Final Kaggle submission (later)

After model selection on the shared validation split, the chosen model may be **retrained on all 10,000
labeled examples** with the selected hyperparameters, then used to predict `test.csv`. A `predict.py`
entrypoint will write `submission.csv` (ID column + probability of AI). Not implemented yet.
